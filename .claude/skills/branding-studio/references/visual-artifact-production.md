# Visual artifact production — make the designed work real

Load this reference when a material deliverable is a designed visual artifact: a logo/wordmark/lockup, reference or mood board, key composition, poster/social/editorial/packaging/signage application, presentation, guideline/brand book, template or another visual touchpoint whose craft must be judged from the artifact itself.

This reference owns the **production loop**, not the identity logic. `identity-craft.md` owns the visual system and craft criteria; `brand-book.md` owns guideline/teaching logic; `visual-production.md` owns generated or edited raster imagery. Use them together when the deliverable crosses those boundaries.

The objective is an actual inspectable artifact whose quality can be judged and reproduced at the claimed maturity—not a description of one.

## Invariants

1. **Make, do not merely specify.** When an adequate production capability exists, create the material visual deliverable rather than stopping at prose, prompts, pseudo-code, wireframes or production instructions.
2. **Choose the surface for the artifact.** Use the strongest available medium for the required control: vector/design canvas for precise geometry and composition; editorial/layout tools for multi-page work; motion-capable surfaces for time-based expression; deterministic/code-native construction for patterns, diagrams or procedural graphics; generated/edited raster production through `visual-production.md` when imagery is the right medium.
3. **Source is not mockup.** A contextual mockup can test scale, material and environment, but it does not replace the underlying master or application source.
4. **Rendered output is visual evidence.** File validity, layer structure or successful tool execution cannot establish hierarchy, optical quality, composition or brand fit. View the result at representative scale/context.
5. **The first successful build starts refinement.** Fix material visual defects before completion; do not stop because the artifact is technically producible.
6. **Capability limits change maturity, not the quality bar.** If no available production surface can realize the committed direction honestly, deliver the strongest truthful lower-maturity state or production brief and expose the blocker.

## 1. Preflight the production path

Before substantial execution, inspect the visual-production capabilities actually available in the host/workspace and choose the smallest path that can produce and inspect the artifact at the required fidelity.

Choose by artifact properties, not tool convenience or prestige. Prefer editable/controlled construction when future operators need to modify the work. Use raster generation only when raster imagery is intrinsically the right medium; do not rasterize precise logos, type, diagrams or layout merely because image generation is available.

For mixed artifacts, assign each part to the medium that can control it best, then integrate and inspect the assembled result.

## 2. Produce the real artifact

Create the artifact in the form appropriate to its job and claimed maturity.

- **Logo, wordmark, symbol or lockup:** construct final geometry in a controlled vector path, refine optically, test relevant scale/monochrome/reversal behavior, and keep only variants real use requires. A generated or traced raster concept is not a final master.
- **Reference or mood board:** compose a visual argument rather than a link/image dump. Select references for decision-changing properties, arrange them so the intended territory and contrasts are legible, and preserve source/provenance only where future work needs it.
- **Brand application:** use real or representative content, dimensions and constraints. Build the application itself; use mockups afterward to test contextual behavior rather than as a substitute for the design.
- **Brand book, standards deck or visual guideline:** use `brand-book.md` for what the document must teach, then design the actual pages/screens/slides with deliberate hierarchy, pacing, image treatment and sequencing. Content completeness is not visual completion.
- **Motion or time-based artifact:** use an inspectable time-based production path and judge timing, transition, hierarchy and reduced-motion/accessibility behavior where relevant; a storyboard alone is a concept unless that is the requested deliverable.

When central photography, illustration, key art, textures or composited imagery are generated/edited, follow `visual-production.md`, persist the accepted assets, and integrate the real files before judging the final composition.

## 3. Work in visual slices

Do not accumulate a large amount of unseen visual production when the environment can show intermediate results.

Use the loop:

`MAKE → RENDER / VIEW → CRITIQUE → REFINE → RE-VIEW`

For complex deliverables, prove representative slices before scaling: the core mark before a logo suite, a representative spread before a full book, one expressive and one dense application before a template family. Scale a solution only after the relevant visual logic survives inspection.

Judge with the applicable macro/meso/micro craft criteria in `identity-craft.md`. Fix the largest causal defect first. Reopen the system or direction only when the artifact exposes a recurring upstream problem rather than a local execution defect.

## 4. Keep production truth explicit

Do not confuse:
- a valid SVG with a well-crafted logo;
- a beautiful mockup with a finished source artifact;
- a complete deck structure with a designed brand book;
- an exported file with successful visual QA;
- a generated image with an integrated finished application.

Use deterministic checks where they can establish exact production properties, then separately inspect the visual result. Preserve source/master files and exports only when the mission needs them; do not create ceremonial asset packages.

## 5. Completion gate

Do not claim a material visual deliverable is final while any of the following is true:
- the deliverable is only described, prompted, outlined or represented by a mockup;
- the claimed master cannot be reproduced or inspected through the available production path;
- a central asset required by the committed direction remains placeholder-quality or unresolved;
- representative viewing exposes a known material hierarchy, composition, optical, legibility or coherence defect;
- the artifact depends on a production capability that is unavailable and no equal-quality alternative exists.

Deliver the actual artifact at the highest truthful maturity available, plus only the source/master, exports, contextual views and production notes future use genuinely needs.
