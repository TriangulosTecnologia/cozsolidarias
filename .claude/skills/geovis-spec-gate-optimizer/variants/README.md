## Order of the first campaign

1. **Fix the corrupted `sizeBy` in the production prompt first.** Measuring pruning against a corrupted
   control measures the corruption. The fix is isolated in `fix-sizeby` precisely so it can go alone.
2. `atual-sem-poda` (control, mandatory) → `agente-tier1` → `agente-tier12`, always serialized: the
   `system` is overwritten on the same test agent.
3. Coverage gate before any efficiency axis. A regression in any `R-*` case discards the variant.

## What is not here, and why

No pruned variant of `INSTRUCTIONS`. The docstring of `instructions.ts` states that the redundancy with
the validators is deliberate — the validator turns a violation into a 422 that the user absorbs, while
the instruction prevents the violation from happening. Proposing pruning there requires eval evidence
against a written decision, not a reading of redundancy. The only change proposed on that side is
factual: the statement *"this application does not serve a tile server"* is false (production serves
`/tiles/caf-h3-*`), and the correct justification is that those URLs are not exposed to the agent.

The cut `source-type-enum` **increases** the prompt by ~8 tokens. It is in Tier 1 anyway: its value is
removing five source types the agent cannot use, not saving tokens.
