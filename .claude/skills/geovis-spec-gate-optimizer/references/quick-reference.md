# Quick Reference: Full-Evalued vs Runtime-Captured

> **Outdated (audit of 2026-10-27).** The evaluation goldens are read from `GEOVIS_GOLDEN_DIR` (default `tmp/specs/full/verifield`), not from `full-evalued/`. The "23 files" count does not match the current directory. See `golden-specs.md`.

Quick reference — does not replace `spec-generation-pipeline.md`, but summarizes the essentials.

---

## Generating Full-Evalued Specs

**What:** Golden corpus (23 files) of what the app actually publishes.  
**When:** At the start of each optimization campaign.  
**Who:** The `dump_golden_specs.mjs` script.

```bash
# From the repo root:
node --experimental-strip-types \
  ~/.claude/skills/geovis-spec-gate-optimizer/scripts/dump_golden_specs.mjs

# Optional: keep raw data (14MB+):
# ... --full
```

**Output:** `src/app/(features)/mapas/specs/full-evalued/`
- `<mode>.json` — one per MapMode (coropletico, pontos, etc.)
- `manifest.json` — git SHA, geovis version, provenance

**Characteristics:**
- Deterministic (always the same output for a given git SHA)
- Never edited by hand
- Raw data elided by default
- Only 14 semantically distinct out of the 23 files
- Only 5 reachable by the agent

**When to update:** Every campaign (before running the variant eval).

## Capturing Runtime-Captured Specs

**What:** Specs generated by the agent in response to prompts during eval.  
**When:** During variant evaluation.  
**Who:** The `run_eval_case.sh` script.

```bash
# Prerequisite: pnpm dev running at http://localhost:3000
# With env var: ANTHROPIC_AGENT_ID=<test-agent-id>

# Run one case:
scripts/run_eval_case.sh \
  "mapa coroplético do IDHM por município" \
  "runs/2026-09-18T14-03-11Z--poda-legend/evals/idhm/output.json"
# (test input in pt-BR, kept verbatim: "mapa coroplético do IDHM por município" = choropleth map of IDHM per municipality)

# Output:
# {
#   "prompt": "...",
#   "httpStatus": 200,
#   "durationMs": 2847,
#   "response": { ... spec or error ... }
# }
```

**Output:** `runs/<YYYY-MM-DD>T<HH-mm-ss>Z--<slug>>/evals/<case>/output.json`

**Characteristics:**
- Immutable once written
- Ephemeral (part of a specific round)
- Never contains raw data (the agent never emits it)
- Carries HTTP status, timing, prompt, and response

**When to run:** For each case in `evals/evals.json`, after provisioning the test agent.

## Comparison: Full-Evalued ↔ Runtime-Captured

**When:** After capturing the runtime-captured output of all cases.

```bash
# Extract the delta (comparable structure) from the golden:
node scripts/project_spec.mjs extract-delta \
  src/app/\(features\)/mapas/specs/full-evalued/coropletico-cafs-percentual.json

# Compare the candidate against the delta:
node scripts/project_spec.mjs compare \
  <delta-golden> \
  runs/2026-09-18T14-03-11Z--poda-legend/evals/cafs-percentual/output.json

# Output:
# {
#   "geometry": 1.0,
#   "form": 0.8,
#   "legendScale": 1.0,
#   "dataset": "to-grader"
# }
```

**Scored axes:**
| Axis | Computable? | What it measures |
|------|-------------|-----------|
| geometry | Yes (code) | Correct geometry (`/geo/...` vs `/api/...`) |
| form | Yes (code) | Cartographic form (polygon, point+sizeBy, etc.) |
| legendScale | Yes (code) | Scale (quantitative vs categorical) |
| dataset | No | Semantics (delegated to `agents/grader.md`) |

## Coverage Gate

**Binary:** Passes or discards the variant.

```bash
# Check whether all R-* cases pass:
for CASE in evals/R-*/output.json; do
  node scripts/score_case.mjs "$CASE"
done
```

**Rule:** If **any** coverage case (`coverageRuleId: "R-*"`) fails:
- The variant is discarded **before** scoring
- Robustness regression = unacceptable

## Checklist: Regeneration and Validation

**Before starting the eval:**
- [ ] Git status clean or committed
- [ ] `node scripts/dump_golden_specs.mjs`
- [ ] `manifest.json` contains the expected git SHA
- [ ] Check `libSchemaVersion` in the manifest — if > 2, **stop** and resync the agent

**Before running `run_eval_case.sh`:**
- [ ] `pnpm dev` running with `ANTHROPIC_AGENT_ID=<test-agent-id>`
- [ ] `evals/evals.json` filled in with prompts
- [ ] Each case marked with `coverageRuleId` or `golden`

**After capturing all `output.json` files:**
- [ ] Run `score_case.mjs` on all `evals/R-*/output.json`
- [ ] Check the coverage gate (100% of R-* must pass)
- [ ] Run `project_spec.mjs compare` on golden cases

**Before approving a change:**
- [ ] coverage-gate.json shows 100% passes
- [ ] benchmark.json/md consolidated
- [ ] Recommendation documented

---

## When Not to Use This Skill

- **Generating a single spec:** Use `geovis-spec-generator` (the agent directly)
- **Resyncing the agent with a new schema:** Use `geovis-spec-agent-creator`
- **Editing specs by hand:** Never — always by deterministic regeneration
